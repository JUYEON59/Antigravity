# 🌐 홈페이지 레퍼런스 분석 스킬 (homepage-reference-analyzer)

본 스킬은 `[리서치 결과]` 파일 및 추가 수집 자료를 바탕으로 5대 핵심 영역(디자인 스타일, 화면 구성, 사용자 흐름, 문구와 콘텐츠, 주요 기능)을 정밀 분석하고 규격화된 UTF-8 `.txt` 리포트를 분권 생성합니다.

---

## 📋 1. 리서치 자료 처리 6대 규칙 (Data Rules)

1. **`[리서치 결과]`라는 이름이 들어간 파일을 항상 기본 리서치 자료로 사용한다.**
2. 사용자가 **"리서치 자료 추가 입력"**이라고 명령하면 이후에 제공하는 파일, URL, 텍스트를 추가 자료로 인식한다.
3. 추가 자료는 기존 자료를 덮어쓰지 않고 기존 데이터셋에 누적/병합(Append & Merge)한다.
4. 기본 자료와 추가 자료의 출처를 구분해서 명확히 기록한다.
5. 같은 홈페이지가 중복되면 하나로 묶되, 발견된 출처는 모두 남긴다.
6. 분석할 때 기본 자료와 추가 자료를 함께 사용한다.

---

## ⚙️ 2. 출력 파일 분할 & 포맷 6대 규칙 (Output File Rules)

- 분석 결과는 모두 UTF-8 .txt 파일로 생성
- TXT 파일당 최대 100개
- 100개 초과 시 001-100, 101-200처럼 분할 (예: `리서치_분석_결과_001-100.txt`, `리서치_분석_결과_101-200.txt`)
- 홈페이지 하나를 분석 결과 1개로 계산
- 홈페이지별 분석, 전체 비교 분석, 최종 인사이트를 각각 분리
- 한 홈페이지의 내용은 두 파일로 나누지 않음

---

## 🧠 3. 8단계 홈페이지 레퍼런스 분석 방법론 (Analysis Workflow)

1. **홈페이지별 개별 분석**: 각 홈페이지별 디자인, 화면 구성, 사용자 흐름, 문구/콘텐츠, 주요 기능, 장단점, 참고할 부분 추출
2. **비슷한 내용 묶기**: 공통적으로 나타나는 요소를 하나의 그룹으로 그룹핑/테마화
3. **등장 횟수 및 비율 확인**: 전체 홈페이지 수 대비 발견 횟수 및 비율(%) 기록
4. **패턴 수치 구분**: 공통 패턴(30% 이상), 반복 패턴(10%~30%), 특이 사례(10% 미만 중 우수 아이디어)
5. **공통점과 차이점 찾기**: 대부분 사용 방식, 업종별 차이, 대립되는 방식, 특정 홈페이지 고유 방식
6. **장점과 문제점 분석**: 패턴 / 사용 홈페이지 / 장점 / 단점 / 어울리는 상황 / 주의할 점 정밀 기록
7. **최종 인사이트 만들기**: 3종 구분(반드시 참고할 공통 방식, 상황에 따라 선택할 방식, 차별화를 위한 독특한 방식) 및 근거 출처 연결
8. **추가 조사 항목 표시**: 추측을 배제하고 '추가 조사 필요 / 확인할 내용 / 현재 부족한 근거' 표기

## 📄 4. TXT 파일 출력 표준 양식 구조 (Schema)

```markdown
# 분석 결과 내용

1. 레퍼런스 수집 목록
- 홈페이지 이름
- URL
- 업종

2. 홈페이지별 분석
- 디자인
- 화면 구성
- 사용자 흐름
- 문구와 콘텐츠
- 주요 기능
- 장점과 단점
- 참고할 부분

3. 전체 비교 분석
- 공통점
- 차이점
- 반복되는 패턴
- 눈에 띄는 사례

4. 최종 인사이트
- 반드시 참고할 공통 방식
- 상황에 따라 선택할 방식
- 차별화를 위해 참고할 독특한 방식
- 우선 참고할 홈페이지
- 적용 시 주의할 점
- 추가 조사가 필요한 내용
```

## 🤖 5. AI가 따라야 하는 10단계 작업 실행 순서 (Execution Steps)

1. 사용자의 분석 목적(홈페이지 레퍼런스 벤치마킹)을 확인한다.
2. 입력 폴더에 있는 자료 목록(`[리서치 결과]` 파일 및 추가 입력 자료)을 스캔한다.
3. 각각의 레퍼런스 자료를 읽는다.
4. 정해진 5대 기준(디자인 스타일, 화면 구성, 사용자 흐름, 문구와 콘텐츠, 주요 기능)으로 내용을 분류한다.
5. 중요한 내용마다 원문 위치(URL, Line)를 명확히 기록한다.
6. 자료들의 공통점과 차이점을 8단계 분석 방법론(30%/10% 패턴 수치)에 따라 산출한다.
7. 사실(Fact)과 AI의 해석(Interpretation)을 엄격히 구분한다.
8. 근거가 부족한 내용은 임의로 추측하지 않고 '추가 조사 필요' 항목으로 표시한다.
9. 정해진 포맷(100개 단위 분할 UTF-8 .txt 파일)으로 분석 보고서를 작성한다.
10. 결과를 최종 검사한다 (누적 데이터 덮어쓰기 여부 및 100개 제한 완결성 확인).
