# 리서치 수행

이 Skill은 리서치 보고서만 작성한다. 트렌드 분석, 제안서, PPT를 함께 만들지 않는다. 결과를 스스로 승인하지 않는다.

## 입력

사용자 요청: `$ARGUMENTS`

1. `${CLAUDE_PROJECT_DIR}/CLAUDE.md`를 읽고 공통 규칙을 따른다.
2. `input/topic.md`, `input/client-brief.md`, `input/references/`를 읽는다.
3. 인수가 비어 있으면 `input/topic.md`를 주제로 사용한다.
4. 인수에 파일 경로가 있으면 프로젝트 내부의 실제 파일인지 확인하고 읽는다.
5. 주제, 목적, 대상, 지역, 기간, 제외 범위를 추출한다.
6. 핵심 범위가 없지만 합리적인 기본값을 쓸 수 있으면 `가정`으로 표시한다. 결과가 크게 달라질 선택만 사용자에게 확인한다.

## 조사 계획

1. 핵심 질문을 3~7개로 정리한다.
2. 질문별 검색어를 한국어와 필요한 경우 영어로 만든다.
3. 필요한 자료 유형과 최신성 기준을 정한다.
4. `references/source-quality.md`를 읽고 자료를 선별한다.

## 조사와 검증

1. 최신성이 필요한 내용은 웹에서 확인한다.
2. 정부, 공공기관, 표준기관, 원 연구, 기업 공식 자료 등 1차 자료를 우선한다.
3. 핵심 수치와 중요한 주장에는 가능하면 독립된 근거를 하나 더 찾는다.
4. 검색 결과의 요약문만 인용하지 말고 원문을 확인한다.
5. 발행일, 조사 기준일, 표본, 지역, 단위를 함께 확인한다.
6. 출처가 충돌하면 차이를 숨기지 말고 기준과 한계를 설명한다.
7. 확인할 수 없는 수치, 인용, URL은 사용하지 않는다.
8. 입력 자료의 의견은 외부 사실처럼 표현하지 않는다.

본문의 핵심 근거에는 `[S01]` 형식의 출처 번호를 붙이고, 같은 번호를 출처 표에 연결한다.

## 작성

1. `templates/research-template.md`의 필수 구조를 사용한다.
2. 사실과 해석을 별도 문단이나 표 열로 구분한다.
3. 각 발견점에 확신 수준과 다음 분석 질문을 쓴다.
4. 자료 부족은 `추가 확인 필요 자료`에 기록한다.
5. 결론을 부풀리지 않고 조사 범위 안에서만 요약한다.

## 저장과 상태

1. 기존 `output/01_research/research-report.md`가 있으면 먼저 `output/01_research/archive/`에 타임스탬프가 있는 이름으로 보존한다.
2. 새 보고서를 `output/01_research/research-report.md`에 저장한다.
3. `output/workflow-status.md`에서 리서치를 `draft`로 변경한다.
4. 기존 리서치가 변경되었으면 트렌드 분석과 모든 하위 단계를 `stale`로 변경하되 파일은 삭제하지 않는다.

## 완료 전 검사

- 모든 핵심 수치에 출처와 기준 시점이 있는가?
- 모든 URL과 자료명이 실제 확인된 것인가?
- 사실, 해석, 가정이 구분되는가?
- 다음 단계가 분석할 수 있을 만큼 근거가 구조화되었는가?
- 템플릿의 자체 검증 항목을 확인했는가?

완료 후 생성 파일, 핵심 발견 3개 이내, 한계, 승인 대상, 다음 명령을 보고하고 멈춘다.
