# PPT 생성과 검증 기준

## 도구 선택 순서

1. 현재 환경에 이미 제공된 프레젠테이션 제작 기능을 확인한다.
2. 없다면 설치된 로컬 라이브러리나 오피스 자동화 기능을 확인한다.
3. 새 패키지 설치가 필요하면 사용자에게 패키지명, 용도, 설치 범위를 설명하고 허가를 받는다.
4. 설치나 생성이 불가능하면 Markdown 3종은 완성 상태로 유지하고 실제 PPT가 생성되지 않았다고 정확히 보고한다.

특정 도구를 사용할 수 있다고 추측하지 말고 실제 사용 가능 여부를 확인합니다.

## 기본 디자인 시스템

- 화면 비율: 16:9
- 권장 여백: 화면 가장자리에서 충분한 안전 여백 유지
- 제목: 28pt 이상 권장
- 본문: 16pt 이상 권장
- 한글 글꼴: 배포 환경에서 흔히 사용할 수 있는 글꼴을 선택하고 대체 글꼴을 고려
- 색상: 본문 대비를 충분히 확보하고 강조색을 1~2개로 제한
- 슬라이드당 핵심 메시지: 1개
- 본문 글머리: 가능하면 3~5개 이내
- 출처: 해당 슬라이드 하단에 읽을 수 있는 크기로 표시

## 시각화 선택

| 내용 | 권장 표현 |
|---|---|
| 시간에 따른 변화 | 선 그래프 또는 타임라인 |
| 항목 간 크기 비교 | 막대그래프 |
| 2~5개 선택지 비교 | 비교표 |
| 단계와 순서 | 프로세스 또는 로드맵 |
| 원인과 결과 | 인과 흐름도 |
| KPI | 숫자 카드와 정의 |

데이터가 없는데 차트를 만들지 않습니다. 장식용 차트, 의미 없는 3D 효과, 과도한 아이콘을 피합니다.

## 내용 일치 검사

각 슬라이드에 대해 다음을 대조합니다.

```text
제안서 원문
→ presentation-outline.md의 핵심 메시지
→ presentation-content.md의 화면 문구와 수치
→ 실제 PPT의 제목·본문·출처
→ presentation-script.md 또는 발표자 노트
```

## 파일 구조 검사

`.pptx`는 ZIP 기반 OOXML 패키지입니다. 최소한 다음을 확인합니다.

- 패키지를 ZIP으로 읽을 수 있다.
- `[Content_Types].xml`이 있다.
- `ppt/presentation.xml`이 있다.
- `ppt/slides/slide*.xml` 수가 구성안의 슬라이드 수와 일치한다.
- 관계 파일과 미디어 참조가 깨지지 않았다.

## 시각 검사

가능한 경우 모든 슬라이드를 이미지나 PDF로 렌더링하고 다음을 봅니다.

- 텍스트 잘림과 겹침
- 빈 자리 또는 의도하지 않은 빈 슬라이드
- 너무 작은 출처와 본문
- 차트 범례, 축, 단위 누락
- 슬라이드 간 제목·번호 불일치
- 글꼴 대체로 인한 줄바꿈 변화

렌더링하지 못했다면 `시각 검사는 미수행`이라고 결과 보고에 남깁니다.
