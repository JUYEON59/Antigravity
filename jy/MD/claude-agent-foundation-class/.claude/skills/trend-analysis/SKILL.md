# 트렌드 분석 수행

이 Skill은 승인된 리서치 자료를 해석한다. 새 시장조사 보고서나 제안서, PPT를 만들지 않는다. 결과를 스스로 승인하지 않는다.

## 승인 게이트

1. `${CLAUDE_PROJECT_DIR}/CLAUDE.md`와 `output/workflow-status.md`를 읽는다.
2. 리서치 상태가 `approved`인지 확인한다.
3. `output/01_research/research-report.md`가 실제로 존재하는지 확인한다.
4. 승인 상태 또는 파일이 없으면 무엇이 필요한지 알리고 중단한다.

## 입력

사용자 요청: `$ARGUMENTS`

- 인수가 비어 있으면 `output/01_research/research-report.md`를 사용한다.
- 다른 경로가 지정되면 그 파일이 승인 대상과 같은 자료인지 확인한다.
- `input/topic.md`와 `input/client-brief.md`도 읽어 분석 목적과 범위를 유지한다.
- `references/trend-scoring.md`를 읽고 분류 기준을 적용한다.

## 분석 절차

1. 리서치의 사실, 사례, 사용자 변화, 기술 변화를 근거 단위로 추출한다.
2. 반복성, 시간 방향, 여러 주체의 동시 변화가 있는 신호를 묶는다.
3. 단일 사례, 캠페인, 일시적 화제는 트렌드로 바로 승격하지 않는다.
4. 각 트렌드의 정의, 근거, 발생 원인, 예상 영향을 작성한다.
5. 원인과 단순 상관관계를 구분한다.
6. 단기 변화와 중장기 변화를 구분한다.
7. 기회와 위험, 반대 신호와 불확실성을 함께 쓴다.
8. 평가 점수는 근거와 함께 부여하고 숫자만으로 정밀한 예측인 것처럼 표현하지 않는다.
9. 제안서에서 다룰 우선 트렌드와 필요한 추가 자료를 제시한다.

외부 검색은 리서치의 누락 여부를 확인할 때만 제한적으로 사용한다. 새 핵심 사실이 필요하면 트렌드 보고서에 몰래 추가하지 말고 `추가 확인 필요`로 표시해 리서치 수정 필요성을 알린다.

## 작성

1. `templates/trend-template.md`의 필수 구조를 사용한다.
2. 모든 핵심 트렌드에 리서치의 출처 번호 또는 절을 연결한다.
3. 트렌드 이름은 변화 방향이 드러나는 결론형 문장으로 쓴다.
4. 시나리오와 예측은 확정 사실이 아니라 조건부 해석으로 표현한다.

## 저장과 상태

1. 기존 `output/02_trend-analysis/trend-analysis.md`가 있으면 `archive/`에 타임스탬프 이름으로 보존한다.
2. 새 분석을 `output/02_trend-analysis/trend-analysis.md`에 저장한다.
3. 상태표에서 트렌드 분석을 `draft`로 변경한다.
4. 기존 분석이 변경되었으면 제안서와 프레젠테이션 단계를 `stale`로 변경하되 파일은 삭제하지 않는다.

## 완료 전 검사

- 모든 트렌드가 리서치 근거와 연결되는가?
- 단일 사례를 시장 전체 변화로 과장하지 않았는가?
- 단기 유행과 구조적 변화를 구분했는가?
- 기회, 위험, 반대 신호를 모두 다뤘는가?
- 제안서에 반영할 우선순위가 설명되는가?

완료 후 생성 파일, 핵심 트렌드 3개 이내, 불확실성, 승인 대상, 다음 명령을 보고하고 멈춘다.
