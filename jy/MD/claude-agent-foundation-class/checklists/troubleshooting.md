# 문제 해결 가이드

## Windows PowerShell에서 `claude.ps1` 실행이 차단됨

PowerShell 실행 정책 오류가 나면 시스템 정책을 임의로 낮추지 말고 먼저 아래처럼 Windows 명령 래퍼를 사용합니다.

```powershell
claude.cmd
```

`claude.cmd --version`으로 설치 상태를 확인할 수 있습니다. 기관 PC의 실행 정책 변경은 관리자 지침을 따릅니다.

## `CLAUDE.md`가 로드되지 않음

1. 프로젝트 루트에서 Claude Code를 시작했는지 확인합니다.
2. 파일명이 정확히 대문자 `CLAUDE.md`인지 확인합니다.
3. `/context`의 Memory files를 확인합니다.
4. `/memory`에서 실제 파일 위치를 확인합니다.
5. 상위 폴더의 다른 지침과 충돌하지 않는지 봅니다.

## Skill이 `/skills`에 없음

1. 경로가 `.claude/skills/<name>/SKILL.md`인지 확인합니다.
2. `SKILL.md`의 대문자와 확장자를 확인합니다.
3. YAML이 첫 줄의 `---`로 시작하고 두 번째 `---`로 닫히는지 봅니다.
4. `name`과 `description` 들여쓰기를 확인합니다.
5. 세션 중 최상위 `skills` 폴더를 처음 만들었다면 Claude Code를 재시작합니다.

## 다음 단계가 실행되지 않음

1. `output/workflow-status.md`에서 직전 단계가 `approved`인지 봅니다.
2. 승인 문장을 사용자 본인이 명시적으로 입력했는지 확인합니다.
3. 직전 결과물 파일이 실제 경로에 있는지 확인합니다.
4. 상위 결과 수정으로 현재 단계가 `stale`이 아닌지 확인합니다.

## 결과가 다른 폴더에 저장됨

1. `CLAUDE.md`의 결과물 경로를 확인합니다.
2. Skill의 저장 절차를 확인합니다.
3. Claude Code를 프로젝트 루트가 아닌 하위 폴더에서 실행했는지 봅니다.
4. 잘못 생성된 파일은 바로 삭제하지 말고 위치를 기록한 뒤 올바른 경로로 정리합니다.

## 출처가 부정확함

1. 검색 결과 요약이 아니라 원문을 엽니다.
2. URL, 발행 기관, 날짜, 조사 범위를 대조합니다.
3. 원문을 확인할 수 없으면 해당 주장을 삭제하거나 낮은 확신으로 표시합니다.
4. 핵심 수치는 공식 통계나 원 연구로 교체합니다.

## PPT를 만들 수 없음

1. 구성안 3개 Markdown 파일이 먼저 완성되었는지 확인합니다.
2. 현재 환경에 PPT 생성 기능이나 라이브러리가 있는지 확인합니다.
3. 설치가 필요하면 강사의 수업 정책과 사용자 허가를 확인합니다.
4. 생성 실패를 숨기거나 파일 확장자만 바꾸지 않습니다.
5. 실패 로그와 미생성 상태를 보고하고 구성안은 보존합니다.

## PPT가 열리지 않음

1. 파일 크기가 0인지 확인합니다.
2. 실제 OOXML ZIP 패키지인지 확인합니다.
3. 다른 이름으로 복사해 다시 열어 봅니다.
4. 생성 도구의 오류와 누락된 미디어 참조를 확인합니다.
5. 기존 파일을 보존하고 새 버전으로 재생성합니다.

## 상위 수정 후 하위 결과가 혼재함

1. 하위 단계 상태를 `stale`로 바꿉니다.
2. 기존 하위 파일은 삭제하지 않습니다.
3. 수정된 근거가 영향을 주는 절과 슬라이드를 찾습니다.
4. 필요한 범위만 다시 생성하고 검토·승인합니다.

## `/workflow-council`에서 팀원이 생성되지 않음

1. Claude Code 버전이 2.1.32 이상인지 확인합니다.
2. `.claude/settings.json`의 `CLAUDE_CODE_EXPERIMENTAL_AGENT_TEAMS` 값이 `1`인지 확인합니다.
3. 설정을 추가한 뒤 Claude Code를 재시작했는지 확인합니다.
4. `/context`와 구성 진단에서 프로젝트 설정이 로드되었는지 봅니다.
5. `.claude/agents/`에 네 에이전트 파일이 있는지 확인합니다.
6. 기관 관리 정책이 실험 기능이나 Agent 도구를 차단하지 않는지 확인합니다.

## 팀원이 서로 대화하지 않고 바로 종료함

1. 단순 서브에이전트가 아니라 Agent Teams 팀원으로 생성되었는지 확인합니다.
2. 팀원 이름이 `research-auditor`, `trend-auditor`, `proposal-auditor`, `presentation-auditor`로 전달되었는지 봅니다.
3. 독립 감사, 초기 공유, 상호 반론, 최종 투표 작업이 만들어졌는지 확인합니다.
4. 리더에게 모든 팀원의 반론이 도착하기 전에 결론을 내리지 말라고 지시합니다.

## 통합 심의의 토큰 사용량이 너무 큼

Agent Teams는 각 팀원이 별도 컨텍스트를 사용하므로 토큰 사용량이 증가합니다. 기본 7차시에서는 생략하고, 최종 프로젝트 한 건에만 선택적으로 실행하거나 팀원을 두 개 관점으로 축소합니다. 두 팀원으로 줄이면 누락되는 관점을 수업 기록에 명시합니다.
