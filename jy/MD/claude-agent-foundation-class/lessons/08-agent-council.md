# 선택 심화 — 전문 에이전트 심의회

## 학습 목표

- Skill과 에이전트의 차이를 설명한다.
- 서브에이전트와 Agent Teams의 소통 구조를 구분한다.
- 서로 다른 전문 관점이 반론하고 합의하는 심의 절차를 실행한다.
- 에이전트 합의와 사용자 최종 승인을 분리한다.

## 개념 구분

```text
Skill
= 특정 작업을 수행하는 지식과 절차

에이전트
= 독립된 컨텍스트에서 역할을 수행하는 실행 주체

서브에이전트
= 결과를 리더에게 반환하지만 서로 직접 대화하지 않음

Agent Teams 팀원
= 공유 작업 목록과 메시지를 사용해 서로 직접 대화함
```

따라서 “Skill끼리 회의한다”는 표현을 실제 구조로 바꾸면 “각 Skill 관점을 맡은 전문 에이전트들이 회의한다”가 됩니다.

## 준비

1. Claude Code 2.1.32 이상인지 확인합니다.
2. 이 패키지의 `.claude/settings.json`에 실험 기능 설정이 있는지 확인합니다.
3. 설정을 처음 적용했다면 Claude Code를 재시작합니다.
4. `/agents` 또는 구성 진단으로 프로젝트 에이전트 4개가 로드되었는지 확인합니다.
5. `output/workflow-status.md`의 리서치부터 실제 PPT까지 모두 `approved`인지 확인합니다.

Agent Teams는 네 개의 별도 Claude 세션을 사용하므로 토큰 사용량이 증가합니다.

## 실행

```text
/workflow-council 전체 결과물의 근거 연결, 실행 가능성, 발표 정확성을 종합 심의해줘
```

호출하면 현재 세션이 리더가 되고 다음 팀원들이 소집됩니다.

| 팀원 | 관점 |
|---|---|
| research-auditor | 출처, 최신성, 수치, 사실·해석 구분 |
| trend-auditor | 변화 근거, 원인·영향, 기회·위험 |
| proposal-auditor | 문제·전략·실행·KPI와 근거 추적 |
| presentation-auditor | 흐름, 원문 일치, 가독성, PPT 검증 |

## 관찰할 협의 과정

1. 네 팀원이 독립적으로 검토한다.
2. 각자 발견 사항을 다른 팀원에게 공유한다.
3. 다른 관점의 주장에 근거를 요구하거나 반론한다.
4. 최초 의견을 유지·수정·철회한다.
5. 각자 최종 판정에 투표한다.
6. 리더가 합의와 이견을 분리해 기록한다.

## 결과물

- `output/05_council/council-decision.md`
- `output/05_council/dissent-log.md`
- `output/05_council/action-items.md`

## 결과 읽기

다음 질문으로 검토합니다.

- 다수결이 아니라 원문 근거로 사실을 판단했는가?
- 최초 의견과 반론 후 의견이 달라진 사례가 있는가?
- 소수 의견을 삭제하지 않았는가?
- `blocking`, `major`, `minor`가 일관되게 적용되었는가?
- 수정 권고가 담당 단계와 재검증 조건을 포함하는가?

## 사용자 의사결정

심의회는 `통과 권고`, `조건부 통과`, `재작업 필요`를 제안할 수 있지만 결과물을 직접 수정하거나 승인하지 않습니다.

심의 결과를 승인하려면 입력합니다.

```text
통합 심의 결과를 승인해. 상태표에 반영해줘.
```

재작업 권고를 적용하려면 수정 범위를 먼저 지정합니다.

```text
action-items.md의 A01과 A02를 적용해줘.
각 항목은 담당 단계의 Skill 절차로 수정하고 하위 상태를 stale로 변경해줘.
```

## 완료 기준

- [ ] 네 팀원이 서로 메시지를 교환했다.
- [ ] 각 팀원이 다른 주장 하나 이상을 검증했다.
- [ ] 합의와 이견이 별도 파일에 기록되었다.
- [ ] 심의회가 기존 결과물을 직접 수정하지 않았다.
- [ ] 최종 승인과 재작업 선택을 사용자가 결정했다.
