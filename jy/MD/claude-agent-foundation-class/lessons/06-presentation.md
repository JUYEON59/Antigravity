# 6차시 — 제안서를 발표 자료로 변환

## 학습 목표

- 문서와 슬라이드의 정보 구조 차이를 설명한다.
- 슬라이드 구성안을 먼저 만들고 검토한다.
- 한 슬라이드에 하나의 메시지를 배치한다.
- 실제 PPT의 내용과 파일 구조를 검증한다.

## 시작 전 게이트

`output/workflow-status.md`에서 제안서가 `approved`인지 확인합니다.

## 1단계 — 구성안 생성

```text
/presentation output/03_proposal/proposal.md를 15분 발표용으로 구성해줘
```

이 단계에서는 다음 세 Markdown 파일만 생성하는 것이 정상입니다.

- `presentation-outline.md`
- `presentation-content.md`
- `presentation-script.md`

## 구성안 검토

1. 1~3장 안에 제안의 핵심을 이해할 수 있는가?
2. 제목만 연속으로 읽어도 이야기가 이어지는가?
3. 슬라이드마다 메시지가 하나인가?
4. 문제 설명보다 해결과 실행에 충분한 장수를 배분했는가?
5. 모든 수치와 출처가 제안서와 같은가?
6. 결론에 청중이 해야 할 결정이 있는가?

## 구성안 수정 예시

```text
5번과 6번 슬라이드가 같은 메시지를 반복해. 하나로 합치고 실행안에 한 장을 더 배정해줘.
모든 제목을 명사형이 아니라 결론형 문장으로 바꿔줘.
14번 KPI 슬라이드에 정의와 측정 주기를 함께 표시해줘.
```

## 2단계 — 승인 후 실제 PPT

```text
슬라이드 구성안을 승인해. 상태표에 반영하고 실제 PPT를 생성해줘.
```

환경에 실제 PPT 생성 기능이 없고 설치가 필요하면 Claude가 허가를 요청합니다. 강사는 수업 전에 사용할 도구와 허용 범위를 정합니다.

## 실제 파일 검토

- 파일 확장자만 `.pptx`인 텍스트 파일이 아닌지 확인합니다.
- 파일을 실제로 열어 모든 슬라이드를 넘겨 봅니다.
- 잘림, 겹침, 작은 글씨, 깨진 한글을 찾습니다.
- 차트의 축, 단위, 범례, 출처를 확인합니다.
- 발표자 노트 또는 별도 원고가 슬라이드 수와 일치하는지 봅니다.

## 수정 요청 예시

```text
8번 슬라이드 본문이 넘쳐. 메시지를 유지하면서 글머리를 4개로 줄여줘.
12번 일정표의 단계 색상을 통일하고 출처 없는 수치는 제거해줘.
발표자 노트가 없는 슬라이드를 찾아 presentation-script.md와 맞춰줘.
```

## 최종 승인

파일을 직접 연 뒤 입력합니다.

```text
실제 PPT를 열어 확인했어. 최종 승인으로 상태표에 기록해줘.
```

## 완료 기준

- [ ] 구성안 3개 Markdown 파일이 있다.
- [ ] 구성안을 승인한 뒤에만 `.pptx`가 생성되었다.
- [ ] 슬라이드 수와 순서가 구성안과 일치한다.
- [ ] 수치와 출처가 제안서와 일치한다.
- [ ] 파일이 정상적으로 열린다.
- [ ] 시각 검사 결과 또는 미수행 사유가 보고되었다.
- [ ] 사용자가 연 뒤 최종 승인했다.
