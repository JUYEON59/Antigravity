# 1차시 — 프로젝트 구조와 `CLAUDE.md`

## 학습 목표

- `CLAUDE.md`의 역할을 설명한다.
- 프로젝트 공통 규칙과 특정 작업 절차를 구분한다.
- Claude Code가 프로젝트 지침을 읽었는지 확인한다.
- 단계 승인과 결과물 경로 규칙을 테스트한다.

## 핵심 개념

`CLAUDE.md`는 프로젝트에서 계속 적용할 규칙을 저장합니다. 한국어 사용, 출처 표기, 결과물 위치, 승인 순서처럼 매 작업에서 반복되는 지침을 둡니다. 리서치 방법처럼 특정 작업에서만 필요한 긴 절차는 Skill로 분리합니다.

```text
항상 필요한 규칙 → CLAUDE.md
특정 작업의 절차 → .claude/skills/<name>/SKILL.md
```

## 실습 1 — 구조 확인

프로젝트 루트에서 다음을 찾습니다.

```text
CLAUDE.md
input/
output/
templates/
.claude/skills/
```

`CLAUDE.md`에서 다음 항목에 밑줄을 긋습니다.

- 단계 승인 규칙
- 상태 값
- 출처 규칙
- 파일 보존 규칙
- 결과물 경로

## 실습 2 — 로딩 확인

1. 프로젝트 루트에서 Claude Code를 실행합니다.
2. `/context`를 입력합니다.
3. Memory files 영역에서 프로젝트 `CLAUDE.md`를 찾습니다.
4. `/memory`를 입력해 프로젝트 지침 파일 위치를 확인합니다.

## 실습 3 — 규칙 이해 테스트

다음 질문을 입력합니다.

```text
이 프로젝트의 작업 단계, 승인 조건, 결과물 경로를 표로 설명해줘.
```

예상 결과:

- 리서치 → 트렌드 분석 → 제안서 → 구성안 → 실제 PPT 순서를 설명한다.
- 각 단계의 승인 조건을 말한다.
- `output/` 아래 파일 경로를 정확히 말한다.

## 실습 4 — 게이트 테스트

아직 리서치를 만들지 않은 상태에서 입력합니다.

```text
/proposal 바로 제안서를 작성해줘
```

정상 동작은 제안서 생성이 아니라, 승인된 트렌드 분석이 필요하다고 안내하는 것입니다.

## 자주 생기는 오류

| 증상 | 확인할 것 |
|---|---|
| `CLAUDE.md`가 보이지 않음 | Claude Code를 프로젝트 루트에서 실행했는가? |
| 규칙을 일부 무시함 | 규칙이 모호하거나 서로 충돌하지 않는가? |
| 파일이 다른 위치에 생김 | 결과물 경로가 정확히 적혀 있는가? |
| 다음 단계가 바로 실행됨 | 상태표와 승인 규칙을 읽었는가? |

## 완료 기준

- [ ] `/context`에서 `CLAUDE.md`를 확인했다.
- [ ] `/memory`로 지침 파일 위치를 확인했다.
- [ ] 공통 규칙과 Skill 절차의 차이를 설명할 수 있다.
- [ ] 승인 없는 단계 건너뛰기가 차단되었다.
- [ ] `output/workflow-status.md`의 상태 값을 이해한다.

## 회고

`CLAUDE.md`에 넣으면 안 되는 긴 절차 하나와, 반드시 넣어야 하는 공통 규칙 하나를 적습니다.
