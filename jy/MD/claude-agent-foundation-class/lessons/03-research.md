# 3차시 — 출처가 있는 리서치

## 학습 목표

- 조사 범위를 먼저 정의한다.
- 최신 자료와 1차 자료를 우선해 조사한다.
- 사실, 해석, 가정을 구분한다.
- 다음 단계가 사용할 구조화된 보고서를 만든다.

## 시작 전 확인

- `input/topic.md`에 주제, 핵심 질문, 지역, 기간, 대상이 있는지 봅니다.
- `input/client-brief.md`에 목표와 제약이 있는지 봅니다.
- 참고 자료가 있다면 `input/references/`에 넣습니다.

## 실행

```text
/research input/topic.md를 기준으로 리서치를 진행해줘
```

Claude가 웹 검색이나 외부 자료 접근 권한을 요청하면 수업 정책에 맞게 허용 여부를 판단합니다.

## 결과 읽는 순서

1. 핵심 요약이 조사 질문에 답하는지 봅니다.
2. 핵심 수치 옆의 `[S번호]`를 출처 표에서 찾습니다.
3. 출처의 발행 주체, 날짜, 조사 범위를 확인합니다.
4. 사실과 해석이 섞이지 않았는지 봅니다.
5. 확신 수준이 낮은 발견과 추가 확인 자료를 찾습니다.

## 수정 요청 예시

```text
S03의 통계가 전체 산업이 아니라 특정 응답자 조사라는 점을 본문에 명시해줘.
경쟁 사례 2개는 공식 제품 문서로 다시 확인해줘.
확인할 수 없는 시장 규모 수치는 삭제하고 추가 확인 필요 자료로 옮겨줘.
수정 전 파일을 archive에 보존해줘.
```

## 승인

검토가 끝나면 입력합니다.

```text
리서치 결과를 승인해. output/workflow-status.md에 반영해줘.
```

상태표의 리서치 행이 `approved`인지 확인합니다.

## 품질 비교 활동

다음 두 문장 중 더 나은 보고서 문장을 고르고 이유를 설명합니다.

```text
A. 모든 디자이너가 AI를 사용하고 있다.
B. 2025년 특정 조사에서 응답한 디자이너 중 일정 비율이 AI 도구를 사용했다고 답했다[S02]. 표본과 지역이 제한되어 전체 시장으로 일반화할 수 없다.
```

B는 대상, 시점, 근거, 한계를 함께 보여 줍니다.

## 완료 기준

- [ ] `output/01_research/research-report.md`가 있다.
- [ ] 최신성이 필요한 정보의 기준일을 확인했다.
- [ ] 핵심 수치에 출처 번호가 있다.
- [ ] 출처 표의 URL 또는 파일을 다시 열 수 있다.
- [ ] 사실·해석·가정이 구분된다.
- [ ] 추가 확인 필요 자료가 숨겨지지 않았다.
- [ ] 상태표에 리서치가 `approved`로 기록되었다.
