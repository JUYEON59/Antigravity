# 강사용 운영 가이드

## 수업 개요

- 대상: Claude Code와 파일 기반 에이전트 작업을 처음 배우는 학습자
- 권장 편성: 차시당 90분, 총 7차시
- 최종 과제: 하나의 주제를 리서치에서 PPT까지 연결한 프로젝트
- 핵심 역량: 프롬프트 작성보다 **컨텍스트, 절차, 상태, 산출물의 연결을 설계하는 능력**

## 수업 전 준비

### 공통 환경

- [ ] 모든 PC에서 Claude Code가 실행된다.
- [ ] 계정 로그인과 네트워크 접속이 된다.
- [ ] 프로젝트 폴더에 한글 경로를 사용할 때 읽기·쓰기가 정상이다.
- [ ] `/context`, `/memory`, `/skills`가 실행된다.
- [ ] 웹 검색 권한과 파일 쓰기 권한의 수업 정책을 정했다.
- [ ] PPT를 열 수 있는 뷰어가 있다.
- [ ] 실제 PPT 생성에 사용할 기능 또는 라이브러리를 사전 테스트했다.
- [ ] 선택 심화 수업을 진행하면 Agent Teams의 실험 기능과 추가 토큰 사용을 안내했다.

### 배포

1. ZIP을 학생별 폴더에 해제합니다.
2. 원본 ZIP은 수정되지 않은 백업으로 보관합니다.
3. `input/topic.md`의 예시를 유지한 공통 시연본과 학생별 주제 실습본을 구분합니다.
4. 웹 검색을 쓸 수 없는 환경이면 검증된 참고 자료를 `input/references/`에 미리 넣습니다.

## 권장 수업 리듬

각 차시를 다음 비율로 운영합니다.

| 구간 | 시간 | 활동 |
|---|---:|---|
| 개념 | 15분 | 오늘 파일이 전체 흐름에서 하는 역할 설명 |
| 강사 시연 | 20분 | 정상 실행과 결과 검토 시연 |
| 안내 실습 | 25분 | 학생이 같은 단계 실행 |
| 개인 적용 | 20분 | 자신의 주제로 수정·재실행 |
| 검증·회고 | 10분 | 체크리스트와 상태표 확인 |

## 매 차시 반복할 질문

1. 지금 적용되는 공통 규칙은 무엇인가?
2. 지금 호출한 Skill의 입력은 무엇인가?
3. 결과의 근거와 한계는 어디에 표시되는가?
4. 다음 단계가 읽을 파일은 무엇인가?
5. 현재 상태는 `draft`인가 `approved`인가?

## 승인 운영

학생은 결과를 읽은 뒤 다음처럼 명시적으로 승인합니다.

```text
리서치 결과를 승인해. 상태표에 반영해줘.
트렌드 분석 결과를 승인해. 상태표에 반영해줘.
제안서를 승인해. 상태표에 반영해줘.
슬라이드 구성안을 승인해. 실제 PPT를 생성해줘.
```

`/proposal`처럼 다음 Skill을 호출하는 행동만으로는 승인되지 않도록 설계되어 있습니다. 이 마찰은 실수가 아니라 검토 지점을 가시화하는 교육 장치입니다.

## 시연할 오류

- `CLAUDE.md`를 잘못된 폴더에 둔 뒤 `/context`에서 누락 확인
- Skill 폴더 이름과 명령 이름의 관계 확인
- 승인 전에 다음 Skill을 호출해 게이트 동작 확인
- 출처 없는 숫자를 발견하고 리서치 수정 요청
- 상위 결과 수정 후 하위 단계가 `stale`로 변하는지 확인
- 구성안 승인 전 PPT 생성 요청을 거부하는지 확인
- 선택 심화에서는 네 전문 에이전트가 실제로 서로 메시지를 교환하는지 확인

## 평가 방법

`checklists/grading-rubric.md`를 사용합니다. 발표 자료의 미적 완성도만 평가하지 말고, 출처 추적성과 단계 연결성을 더 큰 비중으로 평가합니다.
