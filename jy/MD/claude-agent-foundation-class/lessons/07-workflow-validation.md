# 7차시 — 전체 워크플로 검증과 오류 수정

## 학습 목표

- 새로운 주제로 전체 파이프라인을 독립 실행한다.
- 산출물 간 근거와 내용 연결을 추적한다.
- 상위 결과 수정이 하위 결과에 미치는 영향을 관리한다.
- 최종 프로젝트의 재현성과 보존 상태를 검증한다.

## 통합 과제

자신의 주제를 `input/topic.md`에 작성하고 다음 순서로 진행합니다.

```text
1. /context와 /skills 확인
2. /research 실행
3. research-report.md 검토·수정·승인
4. /trend-analysis 실행
5. trend-analysis.md 검토·수정·승인
6. /proposal 실행
7. proposal.md 검토·수정·승인
8. /presentation으로 구성안 생성
9. 구성안 검토·수정·승인
10. 실제 PPT 생성·열기·검증·최종 승인
11. 선택: /workflow-council로 통합 심의 실행
```

## 연결 추적 실습

최종 PPT의 핵심 제안 하나를 골라 역방향으로 추적합니다.

| 단계 | 위치 | 내용 |
|---|---|---|
| PPT | 슬라이드 번호 |  |
| 발표 콘텐츠 | 절 |  |
| 제안서 | 제안·KPI |  |
| 트렌드 분석 | 트렌드 |  |
| 리서치 | 사실·출처 번호 |  |

다섯 단계 중 하나라도 찾을 수 없으면 근거 추적이 끊긴 것입니다.

## 변경 전파 실습

1. 승인된 리서치의 핵심 수치 하나가 잘못되었다고 가정합니다.
2. 리서치 수정을 요청합니다.
3. 기존 보고서가 `archive/`에 보존되는지 봅니다.
4. 트렌드 분석, 제안서, 프레젠테이션 상태가 `stale`인지 확인합니다.
5. 하위 파일이 삭제되지 않았는지 확인합니다.
6. 영향이 있는 부분만 다시 검토하고 승인합니다.

## 오류 주입 실습

다음 중 두 가지를 선택해 해결합니다.

- 출처 URL 하나가 열리지 않는다.
- 트렌드 하나가 단일 사례에만 근거한다.
- KPI의 기준값과 목표값이 없다.
- PPT의 슬라이드 수가 구성안과 다르다.
- 상태표는 승인인데 실제 파일이 없다.
- 상위 결과가 바뀌었는데 하위 상태가 승인으로 남아 있다.

해결 과정에서 파일을 삭제하거나 근거를 새로 만들지 않습니다.

## 최종 검증

`checklists/final-validation.md`를 작성하고, `checklists/grading-rubric.md`로 자기 평가합니다.

## 제출 전 정리

- 임시 파일과 개인 정보가 포함되지 않았는지 확인합니다.
- 아카이브가 현재본과 구분되는지 확인합니다.
- `workflow-status.md`가 실제 파일 상태와 일치하는지 확인합니다.
- 프로젝트 루트에서 재실행 방법을 `START-HERE.md`로 설명할 수 있는지 확인합니다.

## 완료 기준

- [ ] 4개 핵심 Skill을 올바른 순서로 실행했다.
- [ ] 모든 승인 지점이 상태표에 기록되었다.
- [ ] 최종 제안 하나를 출처까지 역추적했다.
- [ ] 상위 수정 시 하위 `stale` 처리를 확인했다.
- [ ] 이전 결과물이 아카이브에 보존되었다.
- [ ] 실제 PPT를 열어 확인했다.
- [ ] 최종 검증표와 자기 평가를 완료했다.
- [ ] 선택 심화 진행 시 합의안, 이견, 조치안이 서로 구분되었다.
