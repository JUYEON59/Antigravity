# 5차시 — 분석을 실행 가능한 제안으로 전환

## 학습 목표

- 트렌드에서 해결할 문제를 정의한다.
- 문제, 목표, 전략, 실행안, KPI를 연결한다.
- 미확정 값과 가정을 투명하게 표시한다.
- 제안의 근거를 리서치 출처까지 추적한다.

## 시작 전 게이트

`output/workflow-status.md`에서 트렌드 분석이 `approved`인지 확인합니다.

## 실행

```text
/proposal output/02_trend-analysis/trend-analysis.md를 바탕으로 제안서를 작성해줘
```

## 논리 연결 검사

제안서에서 다음 사슬을 따라가 봅니다.

```text
리서치 사실
→ 트렌드 해석
→ 해결할 문제
→ 제안 목표
→ 핵심 전략
→ 실행 과업
→ KPI
```

한 단계라도 연결이 끊기면 근거를 추가하거나 제안 범위를 줄입니다.

## 좋은 KPI의 조건

- 무엇을 측정하는지 정의되어 있다.
- 기준값과 목표값을 구분한다.
- 측정 시점과 데이터 출처가 있다.
- 담당 역할이 있다.
- 기준값이 없으면 `사전 측정 필요`로 표시한다.

## 수정 요청 예시

```text
목표 2의 KPI에 기준값이 없어. 숫자를 만들지 말고 사전 측정 계획을 넣어줘.
실행안에 담당 역할과 완료 조건을 추가해줘.
핵심 제안 1이 어떤 트렌드와 출처에 연결되는지 근거 추적표를 보완해줘.
예산은 미확정이므로 TBD로 바꾸고 확정 시점을 제안해줘.
```

## 승인

```text
제안서를 승인해. output/workflow-status.md에 반영해줘.
```

## 동료 검토 활동

두 명이 서로의 제안서에서 다음을 찾습니다.

- 근거 없는 해결책 1개
- 측정할 수 없는 목표 1개
- 담당이 없는 실행 과업 1개
- 숨겨진 가정 1개

발견되지 않으면 `없음`과 확인한 절을 기록합니다.

## 완료 기준

- [ ] `proposal.md`가 있다.
- [ ] 문제와 제안이 직접 연결된다.
- [ ] 실행 일정, 역할, 자원이 있다.
- [ ] 위험 예방과 발생 시 대응이 있다.
- [ ] KPI에 정의, 측정 방법, 주기가 있다.
- [ ] 근거 추적표가 리서치 출처까지 연결된다.
- [ ] 상태표에 제안서가 `approved`로 기록되었다.
