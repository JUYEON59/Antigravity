Claude 에이전트 기초 수업 패키지 사용 가이드
=============================================

1. 패키지 목적
--------------

이 패키지는 하나의 주제를 다음 순서로 연결하는 Claude Code 기초 수업용 자료입니다.

프로젝트 규칙 설정
→ 리서치
→ 트렌드 분석
→ 제안서
→ 프레젠테이션 구성안
→ 실제 PPT
→ 전체 워크플로 검증

앞 단계의 결과물이 다음 단계의 입력이 되며, 사용자가 결과를 승인하기 전에는 다음 단계로 넘어가지 않습니다.


2. 준비 사항
-----------

- Claude Code가 설치되어 있어야 합니다.
- Claude Code에 로그인할 수 있어야 합니다.
- 최신 자료 조사를 위해 인터넷 연결이 필요합니다.
- 최종 PPT 확인을 위해 PowerPoint, Keynote, LibreOffice Impress 또는 호환 뷰어가 필요합니다.
- 실제 PPT 생성 도구나 라이브러리가 필요한 경우 Claude가 설치 허가를 요청할 수 있습니다.

Windows PowerShell에서 claude.ps1 실행 정책 오류가 발생하면 시스템 정책을 임의로 변경하지 말고 다음 명령을 사용합니다.

claude.cmd

설치 버전 확인:

claude.cmd --version


3. 주요 폴더와 파일
------------------

CLAUDE.md
  프로젝트 전체에서 항상 지킬 언어, 출처, 작업 순서, 승인, 파일 보존 규칙입니다.

.claude/skills/
  단계별 전문 작업 절차가 들어 있습니다.

  research/SKILL.md
    자료 조사와 출처 검증을 수행합니다.

  trend-analysis/SKILL.md
    승인된 리서치에서 변화 방향과 의미를 분석합니다.

  proposal/SKILL.md
    승인된 트렌드 분석을 실행 가능한 제안으로 바꿉니다.

  presentation/SKILL.md
    승인된 제안서를 구성안과 실제 PPT로 변환합니다.

  workflow-council/SKILL.md
    네 전문 에이전트를 소집해 상호 검토, 반론, 합의와 이견 기록을 진행합니다.

.claude/agents/
  통합 심의에서 각 Skill의 전문 관점을 맡는 읽기 전용 에이전트 파일이 들어 있습니다.

.claude/settings.json
  Agent Teams 실험 기능을 활성화합니다. 설정을 처음 적용한 뒤 Claude Code를 재시작합니다.

input/
  학생이 작성하거나 제공하는 입력 자료입니다.

templates/
  단계별 결과물의 기본 구조입니다.

output/
  Claude가 생성하는 결과물과 승인 상태를 저장합니다.

lessons/
  강사용 가이드, 1~7차시 학생 실습안, 선택 심화 에이전트 심의 수업안입니다.

checklists/
  명령 참고표, 최종 검증표, 평가표, 문제 해결 자료입니다.


4. 수업 시작 방법
----------------

1) ZIP 파일을 학생별 작업 폴더에 압축 해제합니다.

2) 압축을 해제한 claude-agent-foundation-class 폴더로 이동합니다.

PowerShell 예시:

cd C:\수업폴더\claude-agent-foundation-class

3) input/topic.md를 열어 수업 주제를 작성합니다.

반드시 작성할 항목:

- 주제
- 핵심 질문
- 조사 지역과 기간
- 주요 대상
- 포함 범위와 제외 범위
- 원하는 최종 결과

4) input/client-brief.md를 열어 의뢰 목적과 제약 조건을 작성합니다.

5) 참고 PDF, 이미지, 기존 보고서가 있다면 input/references/에 넣습니다.

6) 프로젝트 루트에서 Claude Code를 실행합니다.

claude

PowerShell 실행 정책 오류가 있으면 다음을 사용합니다.

claude.cmd


5. 구성 파일 확인
----------------

Claude Code가 시작되면 다음 명령을 입력합니다.

/context

확인 사항:

- Memory files에 프로젝트의 CLAUDE.md가 표시되는가?
- Skills에 프로젝트 Skill 설명이 표시되는가?

추가 확인 명령:

/memory
  CLAUDE.md와 메모리 파일 위치를 확인합니다.

/skills
  research, trend-analysis, proposal, presentation, workflow-council Skill이 표시되는지 확인합니다.

Skill이 보이지 않으면 다음을 확인합니다.

- 경로가 .claude/skills/스킬이름/SKILL.md 형식인가?
- 파일명이 대문자 SKILL.md인가?
- Claude Code를 프로젝트 루트에서 실행했는가?
- 세션 중 처음 skills 폴더를 만들었다면 Claude Code를 재시작했는가?


6. 전체 실행 순서
----------------

[1단계: 리서치]

/research input/topic.md를 기준으로 조사해줘

생성 파일:

output/01_research/research-report.md

검토 사항:

- 핵심 수치에 출처와 기준 연도가 있는가?
- 출처 URL이나 파일을 실제로 확인할 수 있는가?
- 사실, 해석, 가정이 구분되어 있는가?
- 확인되지 않은 내용이 만들어지지 않았는가?

검토가 끝나면 다음과 같이 승인합니다.

리서치 결과를 승인해. output/workflow-status.md에 반영해줘.


[2단계: 트렌드 분석]

/trend-analysis output/01_research/research-report.md를 분석해줘

생성 파일:

output/02_trend-analysis/trend-analysis.md

검토 사항:

- 모든 트렌드가 리서치 근거와 연결되는가?
- 단일 사례를 전체 시장의 변화로 과장하지 않았는가?
- 단기 변화와 중장기 변화를 구분했는가?
- 기회와 위험, 반대 신호가 함께 있는가?

검토가 끝나면 다음과 같이 승인합니다.

트렌드 분석 결과를 승인해. output/workflow-status.md에 반영해줘.


[3단계: 제안서]

/proposal output/02_trend-analysis/trend-analysis.md를 바탕으로 제안서를 작성해줘

생성 파일:

output/03_proposal/proposal.md

검토 사항:

- 문제, 목표, 전략, 실행안, KPI가 연결되는가?
- 제안의 근거를 리서치 출처까지 추적할 수 있는가?
- 일정, 담당 역할, 자원, 위험 대응이 있는가?
- 미확정 예산이나 수치를 임의로 만들지 않았는가?

검토가 끝나면 다음과 같이 승인합니다.

제안서를 승인해. output/workflow-status.md에 반영해줘.


[4단계: 프레젠테이션 구성안]

/presentation output/03_proposal/proposal.md를 15분 발표용으로 구성해줘

먼저 생성되는 파일:

output/04_presentation/presentation-outline.md
output/04_presentation/presentation-content.md
output/04_presentation/presentation-script.md

검토 사항:

- 제목만 읽어도 이야기의 흐름이 이어지는가?
- 한 슬라이드에 핵심 메시지가 하나인가?
- 제안서의 핵심 내용이 누락되지 않았는가?
- 수치와 출처가 원문과 일치하는가?


[5단계: 실제 PPT]

구성안 검토가 끝나면 다음과 같이 입력합니다.

슬라이드 구성안을 승인해. 상태표에 반영하고 실제 PPT를 생성해줘.

생성 파일:

output/04_presentation/presentation.pptx

반드시 실제 파일을 열어 다음을 확인합니다.

- 슬라이드 수와 순서가 구성안과 같은가?
- 텍스트 잘림이나 겹침이 없는가?
- 한글 글꼴이 깨지지 않았는가?
- 수치, 차트 단위, 출처가 정확한가?
- 발표자 노트 또는 별도 발표 원고가 있는가?

확인이 끝나면 다음과 같이 입력합니다.

실제 PPT를 열어 확인했어. 최종 승인으로 상태표에 기록해줘.


[선택 6단계: 통합 에이전트 심의]

실제 PPT까지 최종 승인된 뒤 다음 명령을 입력합니다.

/workflow-council 전체 결과물의 근거 연결, 실행 가능성, 발표 정확성을 종합 심의해줘

네 전문 에이전트가 각자 검토한 뒤 서로 메시지를 보내 반론하고 최종 권고를 결정합니다.

생성 파일:

output/05_council/council-decision.md
output/05_council/dissent-log.md
output/05_council/action-items.md

검토 사항:

- 네 팀원이 실제로 서로 메시지를 교환했는가?
- 최초 의견과 반론 후 의견이 구분되는가?
- 합의와 소수 의견이 모두 보존되었는가?
- 수정 권고에 담당 단계와 재검증 조건이 있는가?
- 에이전트가 기존 결과물을 직접 수정하지 않았는가?

심의 결과를 승인하려면 입력합니다.

통합 심의 결과를 승인해. output/workflow-status.md에 반영해줘.

Agent Teams는 별도 Claude 세션 네 개를 사용하는 실험 기능이므로 토큰 사용량이 증가합니다. 에이전트의 합의는 사용자 최종 승인을 대신하지 않습니다.


7. 승인과 상태 관리
------------------

상태는 output/workflow-status.md에 기록합니다.

not_started
  아직 시작하지 않은 단계입니다.

draft
  결과물이 생성되었지만 사용자가 승인하지 않은 상태입니다.

approved
  사용자가 결과를 검토하고 명시적으로 승인한 상태입니다.

revision_requested
  사용자가 수정을 요청한 상태입니다.

stale
  상위 단계가 변경되어 다시 검토해야 하는 상태입니다.

다음 Skill을 실행한 것만으로는 이전 단계가 자동 승인되지 않습니다.

예를 들어 리서치 상태가 draft라면 /trend-analysis를 실행해도 트렌드 분석을 시작하지 않는 것이 정상입니다.


8. 결과물 수정 방법
------------------

수정 요청은 파일, 위치, 문제, 원하는 기준을 함께 작성합니다.

예시:

research-report.md의 S03 통계는 조사 대상과 지역이 제한되어 있어.
이 한계를 본문에 표시하고 수정 전 파일을 archive에 보존해줘.

proposal.md의 KPI 2에는 기준값이 없어.
숫자를 만들지 말고 사전 측정 필요로 변경해줘.

8번 슬라이드의 본문이 너무 길어.
핵심 메시지는 유지하면서 글머리를 4개로 줄여줘.

수정 전 현재 결과물은 각 단계의 archive 폴더에 날짜와 시간이 포함된 이름으로 보존됩니다.

승인된 상위 결과가 변경되면 하위 결과물은 삭제하지 않고 stale 상태로 변경합니다.


9. 최종 검증
-----------

전체 작업이 끝나면 다음 파일을 사용합니다.

checklists/final-validation.md
  구성, 승인, 출처, 연결, PPT, 파일 보존을 확인합니다.

checklists/grading-rubric.md
  100점 기준으로 프로젝트를 평가합니다.

checklists/troubleshooting.md
  파일 로딩, Skill, 승인, 출처, PPT 오류를 해결합니다.

최종 PPT의 핵심 제안 하나를 다음 순서로 역추적할 수 있어야 합니다.

PPT 슬라이드
→ presentation-content.md
→ proposal.md
→ trend-analysis.md
→ research-report.md의 사실과 출처


10. 통합 에이전트 심의 준비
------------------------

통합 심의는 선택 심화 단계입니다.

필수 조건:

- Claude Code 2.1.32 이상
- .claude/settings.json의 CLAUDE_CODE_EXPERIMENTAL_AGENT_TEAMS 값이 1
- 설정 적용 후 Claude Code 재시작
- 리서치, 트렌드 분석, 제안서, 구성안, 실제 PPT가 모두 approved
- stale 또는 revision_requested 단계가 없음

팀원 역할:

research-auditor
  출처, 최신성, 수치, 사실과 해석을 검증합니다.

trend-auditor
  변화 근거, 원인, 영향, 기회와 위험을 검증합니다.

proposal-auditor
  문제, 전략, 실행, KPI와 근거 추적을 검증합니다.

presentation-auditor
  발표 흐름, 원문 일치, 가독성, PPT 검증 기록을 확인합니다.

팀원이 생성되지 않으면 .claude/settings.json 적용과 Claude Code 재시작 여부를 확인합니다. 단순 서브에이전트는 서로 직접 대화하지 않으므로 Agent Teams로 실행되어야 합니다.


11. 권장 수업 순서
-----------------

1차시: 프로젝트 구조와 CLAUDE.md
2차시: Skill 구조와 등록 방법
3차시: 리서치 에이전트
4차시: 트렌드 분석 에이전트
5차시: 제안서 에이전트
6차시: PPT 제작 에이전트
7차시: 전체 연결과 오류 수정
선택 심화: 전문 에이전트 심의회

강사는 lessons/00-instructor-guide.md를 먼저 읽습니다.

학생은 lessons/01-project-rules.md부터 lessons/07-workflow-validation.md까지 순서대로 진행합니다.

전문 에이전트 토론은 lessons/08-agent-council.md에서 진행합니다.


12. 가장 중요한 원칙
-------------------

CLAUDE.md
= 프로젝트 전체에서 항상 적용되는 규칙

SKILL.md
= 특정 작업을 실행하는 전문 절차

Agent
= Skill의 전문 관점을 맡아 독립적으로 검토하는 실행 주체

Agent Teams
= 여러 전문 에이전트가 서로 메시지를 주고받고 합의와 이견을 만드는 협의 구조

리서치 결과
= 트렌드 분석의 입력

트렌드 분석 결과
= 제안서의 입력

제안서
= 프레젠테이션의 입력

사용자 승인
= 다음 단계로 넘어가기 위한 필수 조건

기존 결과물 보존
= 수정 과정과 근거를 다시 확인하기 위한 안전장치
