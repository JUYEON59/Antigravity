[Integrated] TBD Hybrid Beauty Reference Classification Config

이 문서는 CLI 에이전트(LLM 및 분석 툴)가 Phase 1에서 수집된 스킨케어-메이크업 하이브리드 뷰티 브랜드 레퍼런스 데이터를 바탕으로, 기준에 따라 항목을 검증하고 3대 그룹으로 자동 분류하여 인사이트를 컴파일하도록 제어하는 통합 지시서입니다.

Phase 1: Input Data & Approval Gate (입력 및 검증 단계)

1.1 Automation Objective (자동화 목표)
목표: 리서치 단계에서 추출된 브랜드별 데이터(brand_name, url, meta_description, visual_mood, core_ui, copywriting_ratio)를 수신하여 데이터 무결성을 검증하고 분류 작업에 착수합니다.

1.2 Approval Gate & Input Validation (승인 게이트 및 입력 검증)
- 이전 단계(리서치 데이터 수집)의 상태가 `approved` 또는 수집 완료 상태인지 `output/workflow-status.md`를 통해 확인합니다.
- 수집 데이터 파일(`output/01_research/research-report.md` 또는 `output/01_research/references_raw.txt`)의 실제 존재 여부를 검증합니다.
- 미승인 상태이거나 필수 파일이 부재할 경우 작업을 즉시 중단하고 필요한 요소를 보고합니다.

Phase 2: Classification Rules & Drop Criteria (분류 및 폐기 조건)

2.1 Drop Criteria (수집 제외 및 폐기 조건)
다음 조건 중 하나라도 해당하면 분류 대상에서 즉각 제외(Drop) 처리하고 그 사유를 기록합니다.
- 대형 종합 쇼핑몰 UI: 수십 개의 카테고리와 복잡한 레이아웃이 나열된 종합 쇼핑몰 스타일 UI.
- 더마/클리닉 분위기: 피부과/메디컬 느낌이 지나치게 강하여 차갑고 투박한 코스메틱 사이트.
- 복잡한 그래픽/팝업: 지나치게 화려한 그래픽이나 다수의 팝업창으로 간결한 UX 방향성에 위배되는 사이트.
- 접속/중복 문제: 기존 수집 데이터와 중복되거나 웹사이트 접속이 불안정한 곳.

2.2 Category Classification Rules (카테고리 판별 조건)

Category 1: 디자인 무드 중심 (Effortless & Minimal Mood)
- 판별 조건: visual_mood 스캔 결과, 극도로 깔끔한 여백이 존재하며 과도한 장식 요소를 배제하고 절제된 타이포그래피와 텍스처 중심의 정갈한 비주얼을 사용하는 사이트.
- 핵심 키워드: 미니멀, 깔끔한 여백, 텍스처, 정갈함, 절제된 타이포그래피.

Category 2: 하이브리드 기능/UX 중심 (Hybrid UX & Interactive)
- 판별 조건: core_ui 스캔 결과, 스킨케어 효과(성분, 수분감)와 메이크업 효과(발색, 커버)를 동시에 보여주는 직관적인 UI가 뚜렷하게 확인되는 사이트.
- 핵심 키워드: Before/After, 텍스처 줌인, 투명한 사용 가이드, 1-Step.

Category 3: 최우수 롤모델 (Top Hybrid Model)
- 판별 조건: Category 1의 시각적 무드와 Category 2의 기능/UX를 모두 충족하면서, '간결함(Easy & Effortless)' 브랜드 메시지가 웹사이트 동선 및 빠른 결제 UI(Frictionless Checkout)에 자연스럽게 녹아든 사이트.

2.3 Insight Mapping & Statistics (인사이트 연계 및 통계)
- 제외 조건을 통과한 모든 항목에 대해 수집 데이터 항목 기반의 `core_insight`(1~2줄 요약)를 정립합니다.
- 전체 수집 건수, 통과 건수, 카테고리별 비중, Drop 사유별 통계를 집계합니다.
- 판정이 모호한 대상은 `추가 검토 필요` 항목으로 분류하여 사용자의 최종 판단을 유도합니다.

Phase 3: Output & Execution Rules (출력 및 저장/상태 관리 규칙)

3.1 Output Formatting Rules (결과물 출력 및 저장 양식)
- 결과물 저장 위치: `output/02_classification/classification-report.md`
- 기존 파일 존재 시 `output/02_classification/archive/` 폴더에 타임스탬프를 적용하여 보존합니다.
- 템플릿(`templates/classification-template.md`) 규격을 준수하여 작성합니다.

3.2 Workflow Status Management (상태 관리)
- 분류 보고서 생성 후 `output/workflow-status.md`의 분류 단계를 `draft` 상태로 변경합니다.
- 분류 결과 변경 시 영향을 받는 하위 단계(트렌드 분석, 제안서 등)를 `stale` 상태로 갱신합니다.

3.3 Completion Checklist (완료 전 검사)
- 모든 수집 대상에 대해 수집 제외(Drop) 조건 검증이 완료되었는가?
- 카테고리 1, 2, 3 분류 판정에 객관적 속성 근거가 명시되었는가?
- 카테고리별 분류 건수 및 비율이 정확히 집계되었는가?
- 사용자가 검토 및 승인할 대상이 분명히 드러나는가?
