# 분석 수행

이 Skill은 승인된 트렌드 분석 및 제안 자료를 바탕으로 심층 분석과 검증을 수행한다. 검증되지 않은 가설을 확정 사실로 다루지 않으며, 결과를 스스로 승인하지 않는다.

> 승인 게이트, 저장/아카이브, 상태 갱신 등 공통 절차는 `claude.md`를 따른다. 아래는 이 Skill 고유의 조건과 절차다.

## 승인 게이트 (고유 조건)

- 이전 단계(트렌드 분석 또는 제안서)의 상태가 `approved`인지 확인한다.
- 대상 입력 파일(`output/02_trend-analysis/trend-analysis.md` 또는 지정된 입력 파일)이 실제로 존재하는지 확인한다.

## 입력

사용자 요청: `$ARGUMENTS`

- 인수가 비어 있으면 `output/02_trend-analysis/trend-analysis.md`를 기본 입력으로 사용한다.
- `output/01_research/research-report.md` 및 `input/client-brief.md`를 함께 읽어 일관성을 유지한다.
- 다른 경로가 지정되면 해당 파일이 사전 승인된 절차를 거쳤는지 검증한다.
- `references/analysis-criteria.md`가 존재하면 분석 및 검증 기준을 참조한다.

## 분석 절차

1. 입력 자료에서 확인된 사실(Fact), 해석(Interpretation), 가정(Assumption)을 명확히 분리하여 추출한다.
2. 수집된 데이터 간의 상관관계와 인과관계를 구조적으로 분석한다.
3. 단일 사례나 일시적 현상을 일반화된 결론으로 부풀리지 않는다.
4. 분석 대상의 강점, 약점, 기회 요인, 위협 요인을 정밀 도출한다.
5. 주요 수치 및 주장에 대해 출처 간의 데이터 일치 여부를 재검증한다.
6. 데이터 상충이나 불확실성이 발견되면 한계점과 추가 확인 필요 항목으로 명시한다.
7. 분석 결과의 중요도 및 실행 가능성에 따라 우선순위를 매긴다.

## 작성 및 원칙

1. `templates/analysis-template.md`의 필수 구조를 적용한다.
2. 모든 분석 결론에 리서치 및 트렌드 분석의 출처와 데이터 근거를 연결한다.
3. 미확정 수치나 검증 불가능한 가정은 `TBD`, `확인 필요`, `가정`으로 표시하고 검증 방법을 제시한다.
4. 정량 수치는 실제 데이터 근거가 존재하는 경우에만 명시하며, 임의로 추정치를 확정하지 않는다.
5. 결론 문장은 분석 결과와 핵심 논지가 명확히 드러나는 구체적인 문장으로 작성한다.

## 저장과 상태 (고유 경로)

- 결과 저장 위치: `output/04_analysis/analysis-report.md`
- 아카이브 위치: `output/04_analysis/archive/`
- 공통 저장/상태 갱신 절차는 `claude.md`를 따른다.

## 완료 전 검사

- 모든 분석 결론이 기초 데이터 및 리서치 근거와 직접 연결되는가?
- 사실, 해석, 가정이 명확히 구분되어 기재되었는가?
- 확인되지 않은 수치나 데이터를 임의로 지어내지 않았는가?
- 데이터 간 충돌이나 불확실성에 대한 한계점이 기재되었는가?
- 하위 및 다음 단계에서 활용 가능한 논리와 우선순위가 제공되었는가?

완료 후 생성된 파일 경로, 핵심 분석 발견점 3개 이내, 주요 불확실성/한계점, 승인 대상, 다음 실행 추천 명령을 보고하고 중단한다.
