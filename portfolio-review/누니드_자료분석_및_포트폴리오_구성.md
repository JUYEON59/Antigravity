# 누니드 자료 분석 및 취업 포트폴리오 구성

작성일: 2026-10-29. 이 문서는 기존 파일에서 확인한 내용과 포트폴리오 편집 제안을 구분한다. 외부 사이트의 현재 상태는 재조사하지 않았다.

## 1. 조사 범위

프로젝트 파일 243개의 목록과 유형을 조사했다. PDF 6개는 텍스트를 추출했고, HTML 19개를 포함한 텍스트 자료를 추출·검색했다. 이미지 42개는 목록과 연락 인화 형태의 시각 자료로 검토했다. 개별 이미지의 모든 작은 글씨를 판독하거나 HTML을 브라우저에서 실행 검증한 것은 아니다.

Git 내부 데이터, 자격증명·도구 설정 폴더(.agents, .codex, .aws)는 프로젝트 분석 대상에서 제외했다. 교육용 예시, 자동화 코드, 브라우저 로그는 누니드의 실제 산출물과 구분했다.

- `inventory.json`: 파일별 경로, 크기, PDF 페이지 수, 이미지 크기
- `extracted.txt`: PDF·문서·HTML 등에서 추출한 검색용 텍스트
- `image-index.txt`, `contact-sheet-1.jpg`~`contact-sheet-4.jpg`: 이미지 목록과 검토용 모음

## 3. 활용할 수 있는 페르소나

초기 한지민 브리프에 이름이 있는 가상 페르소나 2명이 있다. 원본 PDF의 브랜드명은 NUSEL이므로, 누니드에 적용할 때는 초기 기획을 재구성한 가상 페르소나임을 표시한다.

| 페르소나 | 상황·문제 | 목표 | 디자인 연결 |
|---|---|---|---|
| 이지윤, 31세, IT 서비스 기획자 | 바쁜 출근 준비, 제품 조합의 번거로움, 긴 마케팅 설명 | 핵심 기능과 제형을 빠르게 이해하고 간결한 루틴 선택 | 대표 루틴, 정보 요약 카드, 빠른 보기 |
| 박서연, 23세, 시각디자인과 3학년 | 불규칙한 과제 일정, 제품 비교 피로, 제한된 예산 | 적은 단계로 자연스러운 표현, 납득 가능한 가격 | 제형·피부 표현 이미지, 간결한 분류, 가격 표시 |

실제 인터뷰나 설문으로 검증한 페르소나라는 근거는 확인하지 못했다. user-interview-analyzer의 예시 인터뷰는 프로젝트의 실사용자 조사로 취급하지 않는다.

## 4. 리서치 자료의 성격

`홈페이지 레퍼런스`와 `jy/Antigravity/리서치`에 200개 레퍼런스라고 표기된 목록, 일부 브랜드 분석 CSV, 수집·분류 코드와 지침이 있다. MERIT, ILIA, Saie, Rhode, Typology 등은 기존 문서의 비교 대상이다.

포트폴리오에서는 레퍼런스 목록의 규모보다 다음 연결을 보여주는 것이 유효하다.

- 간결한 제품·루틴 제안 → 누니드 대표 루틴 구성
- 제형과 피부 표현 시각화 → 텍스처와 핵심 기능 중심 정보
- 여백과 명확한 위계 → 한 화면의 핵심 메시지 정리
- 구매 전 판단 정보 제공 → 제품 카드 및 Quick Spec 설계

200개 표기는 고유 브랜드 수·실제 방문 수·검증 완료 수를 보장하지 않는다. 기존 파일의 기능 설명, 색상 코드, 비율을 독립 검증된 시장 통계로 쓰지 않는다. 경쟁사 분석 페이지를 제작할 때 사용할 사례와 원본 캡처를 선별해야 한다.

## 5. 기존 웹·UX 산출물

김유진·한지민 각각의 분석 보고서, 사이트맵(MD/Mermaid/SVG), 서비스 흐름도(MD/Mermaid/SVG), 화면 목록 JSON, 화면 설계서와 HTML 와이어프레임이 있다. 김유진 메인 스토리보드는 1~4차, 별도 웹디자인은 초안·1차·2차가 있다. 사후관리 폴더에는 웹디자인 초안·수정본·최종과 개선 문서가 있다.

핵심 동선은 다음과 같이 정리할 수 있다.

1. 루틴 탐색: 메인 → 대표 루틴 → 단계별 제품 이해 → 세트 선택 → 장바구니
2. 단품 탐색: 메인 → 카테고리 → 기능·제형·가격 확인 → Quick Spec 또는 상세 → 장바구니
3. 신뢰 확인: 브랜드 철학·제품 원칙·제형 확인 → 관련 제품 탐색

사이트맵에 기재된 결제·마이페이지·예외 화면은 실제 완성 화면 여부 및 브리프 범위를 별도로 확인해야 한다. 사이트맵에 존재한다는 이유만으로 완성된 서비스로 표현하지 않는다.

## 6. 포트폴리오에 쓸 개선 사례

사후관리 문서의 네 가지 변경은 수정 전후를 설명할 수 있는 소재다.

| 문제 | 제안·기록된 변경 | 포트폴리오에서 보여줄 것 |
|---|---|---|
| 첫 구매 안심 정보가 하단에 집중 | 상단 띠배너와 세트 주변 안내 | 정보 우선순위의 전후 변화 |
| 모바일에서 15개 제품 나열로 탐색 길이 증가 | 세트 우선 노출 및 전체 제품 6개 우선 표시·펼치기 | 모바일 화면 구조 비교 |
| Quick Spec과 담기 버튼의 동등한 강조 | 담기를 주 행동으로 강조, 스펙은 보조 링크 처리 | CTA 위계 비교 |
| 담기 다음 행동 안내 부족 | 첫 담기 시 카트 드로어, 토스트에 다음 행동 링크 | 담기 이후 인터랙션 흐름 |

문서에는 시선 추적 인지율 15%, 모바일 트래픽 70%, 이탈률 42%, Lighthouse 98점, 명도 대비 4.6:1 등 수치가 있으나 해당 측정의 원본 데이터·보고서를 확인하지 못했다. 실제 검증 성과로 인용하지 않는다. 문서의 PASS도 이번 조사에서 실행 검증한 결과는 아니다.

## 7. 브랜드 아이덴티티와 스타일

로고 초안은 N/D 중심의 세리프 모노그램이며, `패키지/1차/로고.png`에는 n/u처럼 읽히는 검정 곡선형 레터마크가 있다. 두 자료의 관계와 최종 채택 근거는 확인되지 않았다. `로고/output/similar_logo_*.jpg`는 타 브랜드·판매용·워터마크가 있는 레퍼런스를 포함하므로 누니드 자체 제작 로고로 제시하지 않는다.

색상은 여러 안이 병존한다.

| 자료 | 확인한 색상 방향 | 해석 |
|---|---|---|
| 한지민 기획 | 화이트·애쉬 그레이·뮤트 스카이 블루 | 초기 방향 |
| 웹디자인 1·2차 CSS | #20211F, #FBFAF7, #E8EFF2, #C7DCE7, #D68170 | 종이색·미스트 블루·코랄 계열의 적용안 |
| 사후관리 최종 CSS | #FFFFFF, #FAF8F5, #1C1917, #B48C72 등 | 웜 뉴트럴·테라코타 계열의 별도 적용안 |

Pretendard 등의 시스템 폰트 스택이 확인되지만 CSS의 후보 서체를 최종 브랜드 지정 서체로 확정할 수는 없다. 코드의 와이어프레임 상태색·설계용 파랑을 브랜드 컬러에 섞지 않는다. 최종 BI 가이드에는 채택한 안의 색상 역할, 서체, 로고 여백·최소 크기·금지 규정이 필요하다.

## 8. 충돌 및 미확정 사항

- 한지민 원본 PDF는 누셀(NUSEL)인데 파생 분석·설계 문서는 누니드(NUNID)로 표기한다. 이름 변경의 공식 설명은 확인되지 않았다.
- 한지민안은 1-Step·제형 중심 탐색, 김유진안은 대표 루틴과 SUN/FACE/CHEEK/LIP/SET 중심이다. 이를 실제로 검증된 개선 과정이라고 단정하지 않는다.
- 한지민 일정은 8/17 공개·9/1 출시, 김유진 일정은 10/19 공개·11/16 출시다. 모두 가상 브리프의 일정으로 실제 제작 기간·출시 이력과 구분한다.
- 김유진 브리프는 할인 중심 브랜딩을 피하지만 일부 후속 시안은 할인·무료 반품을 강조한다. 최종 브랜드 전략과 구매 보조 정보의 위계를 맞춰야 한다.
- 파일명의 '최종'만으로 여러 폴더의 최종안을 판정할 수 없다.
- 패키지_기획.txt는 대표 상품/그 외 상품 항목만 있고 구체적인 기획은 없다. 패키지 폴더의 긴 PNG는 웹페이지 와이어프레임이며 패키지 완성 목업으로 보기 어렵다.
- 독립적인 앱 화면·앱 IA·앱 고유 기능 명세는 확인하지 못했다. 모바일 웹을 앱 디자인으로 표기하지 않는다.
- 브랜드명 어원, 실제 작업 기간, 개인/팀 구분, 본인 기여율, 지원 직무, 최종 제출 규격·마감은 파일만으로 확정하지 못했다. 문서에 박주연이 작성자로 나오지만 전 작업의 단독 기여를 증명하지는 않는다.

| 15 | 와이어프레임 | 정보 순서를 정한 이유 | 다수 버전 확보 |
| 16 | 웹 메인 디자인 | 브랜드 가치·루틴·제품 판단 정보 | HTML 시안 확보, 최종안 선정 필요 |
| 17 | 제품·브랜드 화면 | 카드·Quick Spec·브랜드 소개의 역할 | 구조·프로토타입 확보 |
| 18 | 개선 과정 | 정보 우선순위·모바일 길이·CTA·담기 이후 동선 | 수정 문서 확보, 전후 비교 제작 필요 |
| 19 | 모바일 웹 | 작은 화면에서 유지할 정보와 행동 | 명세·반응형 코드 확보, 화면 검토 필요 |
| 20~21 | 앱 확장 | 웹과 다른 앱의 사용 목적과 핵심 흐름 | 기존 자료 없음, 제작 시 신규 확장으로 표시 |
| 22 | 결과·회고 | 설계한 범위, 한계, 다음 검증 계획 | 실측 성과 없이 작성 가능 |

앱과 패키지는 빈칸을 채우기 위해 기존 작업처럼 설명하지 말고, 브랜드 전략에 연결해 새로 설계해야 한다. 현재 자료만으로는 웹 설계 과정이 가장 풍부하므로 브랜드 전략 → 시각 체계 → 제품 접점 → 디지털 경험의 연결을 강화하는 편집이 필요하다.

## 10. 후속 제작 기준 제안

브랜드 기본 정의와 타깃은 누니드가 명시된 김유진 원본 PDF를 우선 기준으로 삼는다. 이전 문서는 참고안으로 유지하며 실제 수정 경위는 추정하지 않는다. 실제 리서치 사실, 가상 브리프의 설정, 디자이너의 해석, 신규 제안을 분리한다. 사용자 미응답 상태에서 역할·기간·성과·네이밍 뜻을 임의로 채우지 않는다.
